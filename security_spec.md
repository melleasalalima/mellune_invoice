# Security Specification for Beads Shop System

## 1. Data Invariants

1. **Role Access Bounds**:
   - Only `melleasalalima@gmail.com` can self-bootstrap as `super_admin`.
   - All other self-registrations must default to `user`.
   - Any modification of roles after registration is strictly restricted of `super_admin`.
   - Normal `user` accounts (Viewer/Cashiers) cannot write, update, or delete inventory SKUs.

2. **Inventory Stock Logic**:
   - Stock `quantity` must be a non-negative integer >= 0.
   - Item `price` must be a non-negative number >= 0.
   - Every inventory item must have a unique, system-conforming Stock Keeping Unit (SKU).

3. **Invoice Immutability and State Guards**:
   - Invoice item lists must define a non-zero, positive subtotal.
   - Once an invoice's `paymentStatus` is changed to `paid` or `cancelled`, normal viewer accounts cannot update any field.
   - Deletion of invoice records is restricted to `admin` and `super_admin` to prevent fraud.

4. **Shop Settings Protection**:
   - Only `admin` and `super_admin` can edit shop credit details (such as GCash details or active invoice templates).

## 2. The "Dirty Dozen" Exploit Payloads

Here are the 12 payloads representing targeted security attacks designed to violate safety invariants. All of these *must* be blocked and return `PERMISSION_DENIED`:

### Group A: Identity Elevation & Account Spoofing
1. **Self-Elevating User Role (Anonymous)**
   * Attempt: Unauthenticated user registers and sets `role` to `super_admin`.
   * Action: `create` on `/users/attacker1` with role `super_admin`.

2. **Self-Elevating User Role (Authenticated normal user)**
   * Attempt: User `auth.uid = "user1"` sets their own profile role to `admin`.
   * Action: `create` on `/users/user1` where email is not the bootstrap email but sets `role: "admin"`.

3. **Cross-User Account Hijack**
   * Attempt: User `auth.uid = "user1"` tries to update the displayName of `users/user2`.
   * Action: `update` on `/users/user2` with user1 auth token.

4. **Admin Role Spoofing (Modifying immutable fields)**
   * Attempt: User `auth.uid = "user1"` attempts to update their database profile role from `user` to `super_admin`.
   * Action: `update` on `/users/user1` changing `role: "super_admin"`.

### Group B: Stock Poisoning & Inventory Sabotage
5. **Unauthorized Stock Insertion**
   * Attempt: Standard cashier (`role = "user"`) tries to add a new premium crystal bead SKU.
   * Action: `create` on `/inventory/sku999` with viewer token.

6. **Price Sabotage (Negative Pricing)**
   * Attempt: Rogue cashier/user tries to update a bead price to a negative value to allow cheap purchase checkout.
   * Action: `update` on `/inventory/sku1` setting `price: -250` which violates price boundary checks.

7. **Negative Quantity stock drain**
   * Attempt: CAS-02 account sets a bead stock to `-50`.
   * Action: `update` on `/inventory/sku1` setting `quantity: -50`.

8. **Resource Poisoning (1MB String Attack)**
   * Attempt: Attacker attempts to fill Firestore billing registers with extremely long strings.
   * Action: `create` on `/inventory/sku_huge` with `sku` field size larger than 128 characters or huge description content.

### Group C: Financial Fraud & Invoice Deletion
9. **Direct Invoice Tampering**
   * Attempt: Accessing and updating invoices generated by another employee.
   * Action: `update` on `/invoices/inv5012` modifying total price or lines to dodge audit checks.

10. **Paid Invoice Refunding**
    * Attempt: Unauthorized editor tries to move an invoice from a locked `paid` state back to `unpaid` to siphon cash.
    * Action: `update` on `/invoices/inv100` setting `paymentStatus: "unpaid"` after it was already marked terminal `paid`.

11. **Rogue Record Erasing**
    * Attempt: Normal employee cashier deletes an active invoice list to erase financial transactions before logging off.
    * Action: `delete` on `/invoices/inv1001` using a non-admin token.

12. **Settings Poisoning**
    * Attempt: Client-side script hijacks GKash account number and sets it to attacker's phone number.
    * Action: `update` on `/settings/shop` with Cashier token.
